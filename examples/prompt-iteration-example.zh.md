# 示例：提示词迭代

## 问题

最初的编码提示词产出的代码经常出现以下情况：

- 引入新依赖
- 在 UI 组件里直接调用 API
- 遗漏错误状态
- 修改无关文件

## V1

```text
构建所要求的 React 功能。
```

## 诊断

这条指令几乎没有项目上下文，也没有约束。

## V2 的改动

补充了：

- 技术栈
- 项目规则
- 现有 API 层
- 可复用组件
- 允许改动的文件范围
- 显式的输出 schema
- 验证检查清单

## 结果

这个实验的重点不是得到一个通用的数值基准。真正重要的工程实践是：把失败记录下来、归类，并用它去改进指令系统。

## 经验

提示词工程是迭代式的系统设计：

```text
观察失败
 ↓
归类
 ↓
提出假设
 ↓
只改一个变量
 ↓
评估
```

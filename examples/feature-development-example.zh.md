# 示例：用户表格分页

## 需求

为现有的用户管理表格增加分页。保持现有 API 契约与 UI 组件库不变。

## 上下文

- React + TypeScript
- 现有 UserTable 组件
- 现有 API 客户端
- 现有 Pagination 组件

## 规划者输出

```text
1. 检视 UserTable 的数据流。
2. 确认 API 分页契约。
3. 复用 Pagination 组件。
4. 增加 page/pageSize 状态。
5. 通过现有 API 层传递分页参数。
6. 为翻页与空结果补充测试。
```

## 编码者输出

编码者只改动方案所要求的文件。

## 测试者输出

验收标准：

- 首页正确加载
- 翻页请求到正确的数据
- 每页条数变更正确
- 空页渲染空状态
- API 错误渲染错误状态

## 评审者输出

评审检查项：

- API 层被复用
- 组件内没有直接的 fetch 调用
- 没有重复的状态来源
- 类型保持完整
- 测试覆盖了被改动的行为

## 人工关卡

开发者检查最终 diff，并运行项目的验证命令。

## 这个示例为什么重要

这个示例说明该工作流不是：

> 「让 AI 写个页面。」

而是：

> 需求 → 上下文 → 方案 → 受约束的实现 → 验证 → 评审。

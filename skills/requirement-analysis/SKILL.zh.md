# 技能：需求分析

## 目的

把一条含糊的软件需求，转换成可直接进入实现的规格说明。

## 触发条件

在以下情况使用：

- 需求不完整或含糊
- 功能请求需要拆解
- 缺少验收标准
- 实现范围不清晰

## 输入

- 原始需求
- 产品背景
- 当前架构
- 相关仓库文件

## 上下文策略

只检索可能影响以下内容的上下文：

- 行为
- 架构
- API / 数据契约
- 约束
- 验收标准

## 规则

1. 绝不臆造缺失的业务规则。
2. 显式标注假设。
3. 优先复用现有抽象。
4. 每条功能性需求都必须有验收标准。
5. 在实现之前先识别待确认问题。

## 工作流

```text
原始需求
 ↓
提取角色 / 目标
 ↓
提取约束
 ↓
映射现有系统
 ↓
识别缺口
 ↓
定义验收标准
 ↓
生成实现规格
 ↓
自检
```

## 输出

可直接进入实现的规格说明，包含：

- 目标
- 用户流程
- 需求
- 受影响的区域
- 边界情况
- 验收标准
- 待确认问题

## 验证

- 没有无依据的假设
- 需求可被测试
- 边界状态已覆盖
- 受影响的系统边界已识别

# 架构设计提示词

## 上下文

- 需求：`{{requirement}}`
- 当前架构：`{{architecture}}`
- 技术栈：`{{stack}}`
- 约束：`{{constraints}}`

## 指令

设计能够满足该需求的最小架构改动，同时保持现有项目约定不变。

## 结果

返回：

1. 架构决策
2. 考虑过的替代方案
3. 决策依据
4. 组件 / 服务边界
5. 数据流
6. API 变更
7. 状态管理
8. 错误处理
9. 安全考量
10. 性能考量
11. 迁移 / 回滚方案
12. 实施顺序

## 验证

检查：

- 没有不必要的依赖
- 在合适的地方复用了现有抽象
- 边界是可测试的
- 失败模式已定义
- 向后兼容性已处理
